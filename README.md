# ASF-RandomBotFriends

Плагин для **[ArchiSteamFarm](https://github.com/JustArchiNET/ArchiSteamFarm)**, который периодически рассылает случайные заявки в друзья от имени ваших ботов.

Плагин через случайную паузу в диапазоне `[MinDelayBetweenInvites; MaxDelayBetweenInvites]` секунд выбирает случайного бота, которому есть кому написать, и отправляет заявку одному случайному кандидату из включённых источников. За один тик отправляется не более одной заявки на весь инстанс — пауза до следующего тика розыгрывается заново каждый раз, а не идёт с фиксированным периодом, чтобы не давать Steam ровный, легко фингерпринтящийся ритм запросов.

Источники кандидатов (можно включить один или оба) — у каждого **своя независимая цель по количеству друзей и свой диапазон**, назначаемый случайно каждому боту при первом обращении:

- **Другие боты этого ASF** (`InviteOwnBots`, включён по умолчанию, цель — `[OwnBotsMinFriends; OwnBotsMaxFriends]`) — bot-to-bot, безобидно, все аккаунты ваши. Опционально ограничивается кластерами (`ClusterCount`, см. ниже), чтобы граф дружбы между ботами нельзя было целиком вычислить, найдя всего одного из них.
- **Комментаторы из групп** (`InviteGroupCommenters`, выключен по умолчанию, цель — `[GroupCommentersMinFriends; GroupCommentersMaxFriends]`) — плагин берёт случайную группу из тех, где бот реально состоит участником, **плюс** любые группы из `GroupCommentersTargetGroupIDs` (для них членство не требуется — стена комментариев публичной Steam-группы читается кем угодно), читает последние `CommentsToScan` комментариев на стене группы и предлагает в друзья случайному автору комментария. На практике в такой пул чаще всего попадают люди, сами написавшие в комментариях что-то вроде "add me" — особенно если указать группу, специально созданную для этого (например [Looking For Friends](https://steamcommunity.com/groups/looking4newfriends)) — но это всё равно **заявки незнакомым живым людям**, а не вашим ботам. Это заметно более узнаваемый для Steam паттерн бот-поведения, чем bot-to-bot дружба, и увеличивает риск ограничений на аккаунт сильнее, чем остальные плагины серии. Включайте осознанно.
- Пул комментаторов **не сканируется на каждый тик** — это тоже был бы узнаваемый ритм запросов к steamcommunity.com. Вместо этого он кэшируется на бота и пересканируется раз в случайный интервал `[GroupCommentersMinScanIntervalHours; GroupCommentersMaxScanIntervalHours]` часов (по умолчанию ~раз в сутки, с джиттером ±несколько часов, чтобы не сканировать строго каждые 24:00:00). Между сканами заявки продолжают уходить с обычной паузой между инвайтами — рассылка не привязана к скану, скан только пополняет пул кандидатов.

Цели разделены специально: количество друзей среди своих ботов и количество добавленных незнакомцев из групп считаются и ограничиваются независимо друг от друга (плагин смотрит, кому именно принадлежит каждый принятый/исходящий SteamID — своему боту или нет). Так можно, например, держать `OwnBotsMaxFriends` высоким, а `GroupCommentersMaxFriends` — низким, не смешивая риск-профили этих двух источников в одном счётчике.

### Кластеры (`ClusterCount`)

По умолчанию (`ClusterCount = 1`) источник "другие боты этого ASF" рассматривает вообще всех ботов инстанса как кандидатов — если ботов много, дружба постепенно образует один связный граф на весь флот, и, обнаружив всего одного бота (например по бану/жалобе), через список его друзей можно дойти до всех остальных.

При `ClusterCount > 1` каждый бот детерминированно (по стабильному хэшу своего имени, не зависит от текущего количества ботов и не меняется от рестарта к рестарту) относится к одному из `ClusterCount` кластеров — заявки от источника "другие боты" отправляются **только** внутри своего кластера. Кластер бота не совпадает с "изолированной группой людей": это чисто внутреннее разбиение самого плагина, не Steam-группа и не что-то видимое извне — снаружи выглядит просто как несколько меньших, никак не связанных друг с другом дружеских кругов вместо одного большого.

Если в какой-то момент часть ботов уже успела подружиться без кластеризации (или переместилась в другой кластер после смены `ClusterCount`), плагин **сам постепенно расформировывает** такие межкластерные дружбы — не более одной за тик, тем же ритмом и той же логикой "одно действие со Steam-отношениями за раз", что и обычные заявки, чтобы резкая массовая отписка сама по себе не была подозрительным паттерном.

## Установка

1. Скачайте архив плагина из [Releases](../../releases) и распакуйте в папку `plugins` рядом с ASF (создайте подпапку с именем плагина).
2. Перезапустите ASF.

## Конфигурация

Настройки задаются **глобально**, в `ASF.json`, как дополнительные (нераспознанные ASF) свойства верхнего уровня:

```json
{
	"RandomBotFriendsEnabled": true,
	"RandomBotFriendsMinDelayBetweenInvites": 30,
	"RandomBotFriendsMaxDelayBetweenInvites": 90,
	"RandomBotFriendsInviteOwnBots": true,
	"RandomBotFriendsOwnBotsMinFriends": 2,
	"RandomBotFriendsOwnBotsMaxFriends": 5,
	"RandomBotFriendsClusterCount": 1,
	"RandomBotFriendsInviteGroupCommenters": false,
	"RandomBotFriendsGroupCommentersMinFriends": 1,
	"RandomBotFriendsGroupCommentersMaxFriends": 3,
	"RandomBotFriendsCommentsToScan": 50,
	"RandomBotFriendsGroupCommentersTargetGroupIDs": [103582791438983609],
	"RandomBotFriendsGroupCommentersMinScanIntervalHours": 20,
	"RandomBotFriendsGroupCommentersMaxScanIntervalHours": 28
}
```

| Свойство | Тип | По умолчанию | Описание |
| --- | --- | --- | --- |
| `RandomBotFriendsEnabled` | `bool` | `false` | Включает/выключает плагин. |
| `RandomBotFriendsMinDelayBetweenInvites` | `ushort`, секунды | `30` | Нижняя граница случайной паузы между отправкой заявок в друзья (одна заявка за тик на весь инстанс ASF). |
| `RandomBotFriendsMaxDelayBetweenInvites` | `ushort`, секунды | `90` | Верхняя граница случайной паузы между отправкой заявок. |
| `RandomBotFriendsInviteOwnBots` | `bool` | `true` | Источник кандидатов: другие боты этого ASF. |
| `RandomBotFriendsOwnBotsMinFriends` | `byte` (0-255) | `2` | Нижняя граница случайной цели по числу друзей-ботов для каждого бота. |
| `RandomBotFriendsOwnBotsMaxFriends` | `byte` (0-255) | `5` | Верхняя граница случайной цели по числу друзей-ботов для каждого бота. |
| `RandomBotFriendsClusterCount` | `byte` (1-255) | `1` | На сколько независимых кластеров делить ботов для источника "другие боты" — заявки уходят только внутри своего кластера. `1` = кластеризация выключена (как раньше). См. раздел "Кластеры" выше. |
| `RandomBotFriendsInviteGroupCommenters` | `bool` | `false` | Источник кандидатов: авторы последних комментариев в группах, где бот уже состоит участником. См. предупреждение выше. |
| `RandomBotFriendsGroupCommentersMinFriends` | `byte` (0-255) | `1` | Нижняя граница случайной цели по числу друзей-незнакомцев из групп для каждого бота. |
| `RandomBotFriendsGroupCommentersMaxFriends` | `byte` (0-255) | `3` | Верхняя граница случайной цели по числу друзей-незнакомцев из групп для каждого бота. |
| `RandomBotFriendsCommentsToScan` | `byte` (1-100) | `50` | Сколько последних комментариев группы читать за один запрос, если `InviteGroupCommenters` включён. |
| `RandomBotFriendsGroupCommentersTargetGroupIDs` | `ulong[]` (или строки с числом) | `[]` | Дополнительные Steam-группы (64-битные SteamID, тип "clan") для источника комментаторов — членство бота НЕ требуется, складывается с группами, где бот реально состоит. Формат ID и способ его узнать — как у `RandomGroupJoinsGroupIDs` в [ASF-RandomGroupJoins](https://github.com/buddymurdock/ASF-RandomGroupJoins). |
| `RandomBotFriendsGroupCommentersMinScanIntervalHours` | `byte` (1-255) | `20` | Нижняя граница случайного интервала пересканирования пула комментаторов группы (в часах, на бота). |
| `RandomBotFriendsGroupCommentersMaxScanIntervalHours` | `byte` (1-255) | `28` | Верхняя граница случайного интервала пересканирования. |

Если оба источника выключены, плагин один раз пишет предупреждение и ничего не делает. Если `Min` больше `Max` в любой из пар (включая паузу между заявками), значения меняются местами автоматически. Заявки отправляются только тем, с кем ещё нет никаких отношений (не друг, заявка не отправлена/не получена, не заблокирован), и никогда — самому себе или другим ботам этого же ASF через источник комментариев. Цель `OwnBotsMinFriends` физически ограничена количеством остальных ботов в этом же ASF — если она больше, чем `количество ботов − 1`, плагин один раз выведет предупреждение в лог.

> Начиная с этой версии `RandomBotFriendsDelayBetweenInvites` (фиксированная пауза, из версий до 1.3.0.0) заменена на пару `RandomBotFriendsMinDelayBetweenInvites`/`RandomBotFriendsMaxDelayBetweenInvites` — раньше плагин бил в Steam с точностью до миллисекунды каждые N секунд без остановки, что само по себе узнаваемый машинный паттерн; теперь пауза до следующего тика розыгрывается заново каждый раз. Если у вас уже настроен `ASF.json` со старым именем — переименуйте свойство (можно указать оба новых с одинаковым значением, чтобы сохранить старое поведение без джиттера, либо задать реальный диапазон).
>
> Ранее в этой же версии 1.1.0.0 `RandomBotFriendsMinFriends`/`RandomBotFriendsMaxFriends` уже были переименованы в `RandomBotFriendsOwnBotsMinFriends`/`RandomBotFriendsOwnBotsMaxFriends` — не перепутайте со свежим переименованием паузы выше.

Важно: в цель (`target`) засчитываются не только принятые заявки, но и уже отправленные, но пока не принятые (`RequestInitiator`) — это тормоз, особенно важный для источника комментариев. Незнакомцы чаще всего не принимают заявки от ботов, и без этого правила бот слал бы заявки бесконечно, потому что "текущих друзей" по факту всегда меньше цели. С этим правилом бот один раз выбирает до `target` кандидатов и замолкает, даже если никто не ответил. Скан пула комментаторов дополнительно ограничен — не более одного реального запроса к steamcommunity.com за тик (если сразу у нескольких ботов истёк кэш, досканируют по одному в следующих тиках, а не все разом); чтение уже закэшированного пула этого ограничения не касается.

## Сборка

Проект использует **[ASF-PluginTemplate](https://github.com/JustArchiNET/ASF-PluginTemplate)** и собирается вместе с исходниками ASF, подключёнными как git submodule:

```sh
git clone --recurse-submodules https://github.com/buddymurdock/ASF-RandomBotFriends.git
cd ASF-RandomBotFriends
dotnet build -c Release
```

Если репозиторий уже склонирован без `--recurse-submodules`, подтяните submodule отдельно:

```sh
git submodule update --init --recursive
```
